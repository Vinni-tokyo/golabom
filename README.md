# 골라봄 (가칭) — Phase 0 프로토타입

YouTube 를 「추천받아 보는 곳」에서 「골라서 보는 곳」으로. 취향을 고르면 좋은 검색어와 필터를 대신 만들어 YouTube·Google 검색을 연다.
독립 사이트: https://vinni-tokyo.github.io/golabom/ · 웹앱 https://vinni-tokyo.github.io/golabom/app/ · 비밀번호 없이 공개(2026-10-30 비밀번호 문 제거).
원래 [dokadoka-cards](https://github.com/Vinni-tokyo/dokadoka-cards) 의 `golabom/` 에서 시작해 2026-10-29 이 저장소로 분리했다.

## Step 0 웹앱 (`app/`, 2026-10-30) — 기획: [docs/PLAN_v0.3](docs/PLAN_v0.3_2026-10-30.md)
2주 재방문 검증용 — **어떤 모드가 사람을 다시 오게 하는가**. 네 모드: **🔥 최신 트렌드**(걸러 낸 인기 급상승) · **내 토픽**(첫 방문 관심 고르기 → 영상 10편 이내) · **🔭 깊이 파기**(숨은 보석 점수) · **리저브**(운영자가 고른 5편, 어두운 바탕·금색). 영상은 앱 안에서 재생, 👍/👎. 이력은 내 토픽의 출발점으로만. 휴대폰 우선, PC 에서는 넓게. 빌드 없음(ES 모듈).

| 파일 | 하는 일 |
|---|---|
| `app/data/topics.json` | 토픽(이름 기반 고정 ID) · 테스터 A~E 예시 토픽 · 트렌드 분야 6 · 깊이 파기 분야 5 × 키워드 6 — 인터뷰 후 이 파일만 바꾼다 |
| `app/data/reserve/<테스터>-<호>.json` | 리저브 원본: **영상 ID + 코멘트만**. 새 호 = 파일 하나 추가 |
| `app/data/gen/` | 자동 작업이 만든 영상 정보 — **커밋 금지**(API 데이터 30일 규정, `.gitignore`) |
| `app/data/sample/` | 키 없이 화면을 보는 샘플(지어낸 자리 데이터, API 데이터 아님 → 커밋함). `gen/` 이 없을 때 앱이 이것을 쓴다 |
| `app/keywords.js` | 지금 뜨는 키워드: 인기 급상승 영상의 제목·태그에서 2개 이상 채널이 함께 쓴 말(API 추가 호출 없음) |
| `worker/` | 검색 중계(Cloudflare Worker): 키를 숨기고 YouTube 를 대신 검색 · 같은 검색은 KV 에 하루 저장 · 새 검색 하루 40번 상한 · 골라봄 주소만 허용. 배포 `cd worker && npx wrangler deploy`, 키는 Cloudflare 대시보드 비밀값 `YT_API_KEY` |
| `app/config.js` | 큐레이터 서명 · 방문 기록(GoatCounter) 주소 · 길이 칩 |
| `tools/fetch_videos.py` | 매일 자동 작업. `--sample` 은 키 없이 화면 확인용 자리 데이터 |
| `.github/workflows/daily.yml` | 매일 오전 6시 받아서 Pages 로 배포(키가 없으면 건너뜀) |

**로컬에서 보기:** `python3 -m http.server 8765`(샘플은 커밋돼 있음 · 다시 만들기 `python3 tools/fetch_videos.py --sample`) → `http://localhost:8765/app/?t=A`
**테스터 링크:** `…/app/?t=A` (평소) · 리저브 발송용 `…/app/?t=A&src=r#/r/A/1` — `src=r` 로 온 방문은 재방문 판정에서 뺀다.
**지금 뜨는 키워드(10-30):** 나라별 탭(한국·미국·일본·중화권 대만/홍콩·영국·인도·프랑스·브라질 — 중국 본토는 YouTube 가 없어 인기 목록이 없음) · 1시간마다 새로 받음(나라·분야 14곳 × 1단위 ≈ 하루 340단위) · 화면에 최종 업데이트 시각. 일본어·중국어는 태그·괄호·해시태그로 키워드를 뽑는다.

**검색 Worker 운영 중(10-30):** https://golabom-search.golabom.workers.dev — Cloudflare 계정 songnchant(무료) · KV `SEARCH_CACHE` · 비밀값 `YT_API_KEY`(대시보드에서 등록, GitHub 자동 작업과 같은 키) · 새 검색 하루 40번. 코드 고친 뒤 `cd worker && npx wrangler deploy`.

**검색(10-30):** 결과를 먼저 보여 주고 버튼으로 좁힌다 — 어떤 영상(새로 찾음) · 길이 · 언제 · 빼기 · 순서(받아 둔 50편 안에서 거름, API 추가 없음). `config.js` 의 `searchApi`(Worker 주소)가 비어 있으면 골라봄이 모아 둔 영상에서 찾는다. YouTube 로 내보내는 링크는 없앴다(우리 화면에서 끝낸다).

**첫 화면은 Google 처럼(10-30):** 로고 · 큰 검색창 · 지금 뜨는 말 5개 · 섹션 바로가기만. 검색하면 첫 화면이 위로 줄고 결과가 바로 아래에(모아 둔 영상 전체: 리저브·트렌드·깊이 파기·토픽). 아래로 내리면 섹션이 이어진다.

**홈 한 화면(10-30 사용자 요청):** 🔥 지금 뜨는 키워드 → 영상 · RESERVE 5편(표지 없이 바로) · 🔭 깊이 파기(검색창 + 키워드 칩, 구독자 100만 초과 채널 제외) · 당신이 주로 즐기는 영상들(내 토픽, 맨 아래·그 자리에서 고르기). 예전 하위 화면 주소(`#/t/…`, `#/d/…`, `#/trend/…`, `#/r/…`)는 링크 호환용으로 남김. 깊이 파기 검색은 골라봄이 모아 둔 영상 안에서 찾고, 없으면 YouTube(4~20분) 링크를 준다 — 임의 검색어의 실시간 보석 찾기는 Worker 가 필요(나중).

**고친 뒤 배포할 때:** Pages 는 JS·CSS 를 10분 캐시한다. `app/index.html` 과 `app/app.js` 의 `?v=날짜+글자` 를 함께 올려야 사용자 화면이 바로 바뀐다.

**운영 중(2026-10-30~):** API 키 = 개인 Google 계정 `golabom` 프로젝트의 `golabom-youtube`(YouTube Data API v3 만 허용) → 저장소 비밀값 `YT_API_KEY`. Pages Source = GitHub Actions.
- 매일 6시(KST) 전부(약 5,100단위) + 매시 35분 지금 뜨는 영상만(14단위) + 수동 실행(full/trend 선택). **푸시할 때는 API 를 부르지 않고** Actions 캐시의 마지막 데이터로 배포한다.
- 한도 초과(403)는 남은 항목을 건너뛰고, 429(너무 잦음)는 20·60초 기다렸다 다시 시도한다. 빠진 항목은 `gen/meta.json` 의 `failed` 에 남는다.
- 워크플로 파일을 고쳐 푸시하려면 토큰에 `workflow` 권한이 있어야 한다(classic 토큰 "Dokadoka" 에 추가함).

## Phase 0 범위 (작업 계획서 v0.1, 2026-10-29)
- 단일 HTML(`index.html` 하나) · 빌드 없음 · 서버/API 없음 — 링크만 만든다(영상 정보를 가져오지 않음)
- 입력 4단계: ① 원하는 것(주제·구체적으로·목적) ② 지금 상황(수준·길이·올린 시기·언어·자막) ③ 피하고 싶은 것 ④ 탐험 정도(0 정확 / 1 넓게 / 2 취향 밖으로)
- 결과(언어별): 정확 검색 · 깊게 · 재생목록 · 채널 · 다른 관점 · Google 정밀 검색 + **비교용 그냥 검색**. 입력이 바뀌면 바로 갱신
- 「구체적으로」는 한국어 검색어에만(번역 안 함) → **AI 프롬프트 복사**로 영어·일본어 검색어를 받아 쓴다
- 기록은 이 브라우저 localStorage 에만: `ytg_profile` · `ytg_history`(연 카드) · `ytg_feedback`(👍/👎) → **기록 내보내기(JSON)**

## 검색어 규칙
`[주제(언어별)] + [구체적으로(한국어만)] + [수준] + [목적 형식어] + [제외어]` — 사전은 `index.html` 의 `TOPICS · GOALS · LEVELS · AVOIDS` 표.

## YouTube 필터 `sp=` (비공식 — 바뀌면 `index.html` 의 `SP` 표만 고친다)
protobuf → base64. 바깥 필드 1 = 정렬, 필드 2 = 필터 묶음 {1 올린 시기 · 2 유형 · 3 길이 · 5 자막}.

| 필터 | 필드 | 값 |
|---|---|---|
| 올린 시기 | 1 | 2 오늘 · 3 이번 주 · 4 이번 달 · 5 올해 |
| 유형 | 2 | 1 동영상 · 2 채널 · 3 재생목록 |
| 길이 | 3 | 1 4분 미만 · 2 20분 이상 · 3 **4~20분** |
| 자막 | 5 | 1 |
| 정렬(바깥 1) | – | 0 관련성 · 3 조회수 |

검산(2026-10-29, 알려진 값과 일치): 20분 이상 `EgIYAg==` · 자막 `EgIoAQ==` · 동영상 `EgIQAQ==` · 재생목록 `EgIQAw==` · 채널 `EgIQAg==` · 이번 달 `EgIIBA==` · 조회수순 `CAM=`.
※ 계획서 7번의 「중간 3~20분」은 YouTube 기준 **4~20분**이다(화면 표기도 4~20분).

## 주간 확인 (계획서 리스크 1)
열기 ↗ 로 YouTube 를 열어 필터 칩(동영상·길이·자막)이 켜져 있는지 본다. 꺼져 있으면 `SP` 표를 고친다.
