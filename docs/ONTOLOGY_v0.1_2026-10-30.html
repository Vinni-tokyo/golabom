골라봄 토픽 지도(온톨로지) 준비안 v0.1

  • 작성: 2026-10-30
  • ➡️ Step 0 범위는 기획 v0.3: 토픽 약 20개 · 한국어만 · 상하위 길만 · 이름 기반 고정 ID 규칙만 먼저 지킵니다. 이 문서의 나머지는 Step 1 이후입니다.
  • 관련: 기획 v0.2 — 모드 네 개가 모두 이 지도 위에서 움직입니다.

0. 쉽게 읽는 요약

예시. 캠핑 의자 영상을 다 본 사람이 있습니다. 목록형 서비스는 여기서 끝납니다. "캠핑 의자 영상 10개"를 보여 주고 나면 더 줄 것이 없습니다. YouTube 는 이 사람을 비슷한 캠핑 의자 영상으로 계속 끌고 갑니다.

원인. 토픽이 서로 연결되지 않은 목록이기 때문입니다. 목록은 "어디까지 왔고, 다음엔 어디로 갈 수 있는지"를 모릅니다.

바꿀 것. 토픽을 지도로 만듭니다. 토픽과 토픽 사이에 이름이 붙은 길을 깝니다.

  • 캠핑 의자 → 다음 단계 → 백패킹 경량화
  • 캠핑 의자 → 같이 필요한 것 → 캠핑 테이블
  • 캠핑 의자 → 상황 → "첫 캠핑 준비" 묶음
  • 동계 차박(뜨는 말) → 이 말이 속한 곳 → 캠핑 > 차박

그러면 영상을 다 본 사람에게 "다음엔 이쪽은 어때요? (다음 단계)" 처럼 이유가 있는 다음 길을 보여 줄 수 있습니다. 알고리즘은 "비슷한 것 더"만 주지만, 골라봄은 어디로 가는 길인지 말해 줍니다. 이것이 차별점입니다.

준비 방법. 처음부터 크게 만들지 않습니다.

  1. 뼈대 (2주): 토픽 약 300개를 LLM 초안 + 사람 검수로 만듭니다.
  2. 키우기 (매일): 모은 영상과 뜨는 말로 토픽과 길을 늘립니다. 새 토픽은 사람이 승인합니다.
  3. 재기: "길을 따라간 사람이 만족했나"를 잽니다.

결정할 것. 3가지입니다(§9).

1. 왜 목록이 아니라 지도인가

목록 (지금 기획) 지도 (제안)
영상을 다 본 뒤 끝. 다시 처음부터 고름 다음 길이 이유와 함께 보임
처음 쓰는 사람 대분류 8개 중 고르기 같음 + 상황 묶음("이사 준비")으로 한 번에
뜨는 말 떠다니는 단어 지도의 한 자리에 붙음 → 깊이 파기로 이어짐
리저브의 "취향 밖 1편" 감으로 고름 내 관심에서 두 걸음 떨어진 곳으로 정의
다른 언어 영상 검색어를 번역 토픽마다 한·일·영 이름과 검색어를 미리 가짐
따라 하기 쉬움 어려움 — 지도와 길은 쌓은 시간만큼 두꺼워짐

마지막 줄이 중요합니다. 화면은 금방 따라 할 수 있지만, 잘 다듬은 토픽 지도는 따라 하기 어렵습니다. 이것이 서비스의 자산입니다.

2. 지도의 생김새: 네 층

예: 「캠핑 의자」 주변의 지도 — 상자는 토픽, 화살표는 이름 붙은 길

층 무엇 예
① 토픽 볼거리의 자리. 크기는 대 · 중 · 소 3단 아웃도어 > 캠핑 > 캠핑 의자
② 길 (관계) 토픽과 토픽 사이의 이름 붙은 연결 캠핑 의자 —다음 단계→ 백패킹 경량화
③ 결 (패싯) 토픽과 상관없이 영상을 나누는 축 영상 종류 · 깊이 · 길이 · 분위기 · 말하는 사람 · 언어
④ 영상·채널 실제 영상과 채널이 토픽과 결에 붙음 "3년 쓴 캠핑 의자 후기" → 캠핑 의자 · 후기 · 8분

검색은 "토픽 × 결"의 조합입니다. 예를 들어 캠핑 의자 × 후기 × 20분 안쪽 × 한국어. 이 조합이 뒤에서 검색어와 필터로 바뀝니다. 사용자는 검색어를 보지 않습니다.

길의 종류 (7가지)

길 뜻 예 화면에서
상위·하위 큰 것과 그 안의 것 캠핑 ⊃ 캠핑 용품 ⊃ 의자 토픽 버튼 내려가기
다음 단계 하나를 알면 그다음에 볼 것 핸드드립 기초 → 물줄기 → 추출 변수 "다음 단계" 칩 · 깊이 사다리
같이 필요한 것 함께 고르거나 함께 쓰는 것 캠핑 의자 ↔︎ 캠핑 테이블 "같이 보면 좋은 것"
상황 묶음 한 상황에 필요한 토픽 여러 개 첫 캠핑 준비 = 텐트 + 침낭 + 의자 + 버너 홈의 "상황으로 고르기"
비교·대안 같은 목적의 다른 선택 텐트 ↔︎ 차박 "다른 방법"

뜨는 말 연결 오늘의 화제가 속한 자리 "동계 차박" → 캠핑 > 차박 트렌드 → 깊이 파기로 이어 가기

결 값 쓰는 모드

리저브의 취향 축(기획 §6-2)은 이 결의 값을 사용자별 가중치로 가진 것입니다. 따로 만들지 않고 같은 결을 씁니다.

3. 토픽 한 개에 담는 것

토픽 하나는 아래처럼 생깁니다. 원본은 사람이 읽고 고칠 수 있는 YAML 로 둡니다.

- id: outdoor.camping.gear.chair        # 위치가 아니라 이름으로 만든 고정 ID — 바뀌지 않음
  level: 소
  name: {ko: 캠핑 의자, ja: キャンプチェア, en: camping chair}
  alias: {ko: [캠핑체어, 릴렉스 체어], ja: [アウトドアチェア], en: [camp chair]}
  query:                                 # 이 토픽을 찾는 검색어(사용자에게는 안 보임)
    ko: 캠핑 의자
    ja: キャンプチェア
    en: camping chair
  exclude: {ko: [-쇼츠], ja: [], en: []}  # 이 토픽에서 자주 섞이는 엉뚱한 영상 빼기
  wikidata: Q...                         # 있으면 연결(다국어 이름·고정 ID 확인용)
  edges:
    parent: outdoor.camping.gear
    next: [outdoor.backpacking.ultralight]
    with: [outdoor.camping.gear.table]
    situation: [situation.first_camping]
    alternative: []
  facets_default: {kind: [후기, 비교], length: 20분}
  channels: []                           # 이 토픽을 잘하는 채널(자동 작업이 채움)
  status: 승인                            # 초안 · 검수 중 · 승인

처음부터 지킬 규칙

이 규칙들은 이전 프로젝트(스킬 사전)에서 실제로 문제가 된 것들입니다.

  • ID 는 이름으로 짓고 절대 바꾸지 않는다. 번호 순서로 지으면 다시 만들 때 번호가 밀려서, 저장해 둔 기록이 소리 없이 엉뚱한 토픽을 가리킵니다.
  • 세 언어가 같은 ID 에 같은 정확도로 붙는다. 한국어만 잘 되고 일본어는 대충이면 안 됩니다. 검수할 때 세 언어를 한 줄에 놓고 봅니다.
  • 같은 말 다른 뜻을 먼저 잡는다. "기타"는 악기(guitar)이기도 하고 "그 밖의 것"이기도 합니다. "배"는 과일·몸·탈것입니다. 별칭이 두 토픽에 겹치면 검사 스크립트가 경고합니다.
  • 검사 스크립트로 막는다. ID 중복, 세 언어 빠짐, 부모 없는 토픽, 없는 ID 를 가리키는 길, 별칭 충돌을 커밋 전에 자동으로 검사합니다.

4. 준비 단계

A. 뼈대 만들기 (약 2주)

  1. 범위를 좁게 정합니다. 처음은 약 300개입니다.
    • 생활 정보 대분류 8 × 소분류 5 = 40
    • 깊이 파기 분야 15 × 하위 10~15 = 약 200
    • 상황 묶음 30, 트렌드 분야 6, 공통 상위 토픽
  2. LLM 이 초안을 씁니다. 분야마다 하위 토픽, 세 언어 이름과 검색어, 길 후보를 만듭니다.
  3. 검색으로 확인합니다. 토픽마다 검색어로 영상 10개를 실제로 받아 보고, 엉뚱한 영상이 섞이는지 봅니다. 섞이면 검색어와 빼기 말을 고칩니다.
  4. 사람이 검수합니다. 분야별로 표본을 보고 승인합니다. 길은 "이 길을 따라가면 정말 다음에 볼 만한가"로 판단합니다.
  5. Wikidata 연결 (선택): 큰 토픽은 Wikidata 항목과 연결해 다국어 이름을 맞춥니다. YouTube 도 영상마다 Wikipedia 주제 링크(topicDetails)를 주므로, 영상을 토픽에 붙일 때 단서로 씁니다.

B. 데이터로 키우기 (매일 자동 + 주 1회 사람)

무엇을 어떻게 사람이 할 일
영상 붙이기 자동 작업이 받은 영상의 제목·설명·Wikipedia 주제를 보고 토픽과 결에 붙임 없음 (표본만 확인)
채널 붙이기 한 토픽에 좋은 영상을 자주 올리는 채널을 "이 토픽을 잘하는 채널"로 기록 없음
새 토픽 후보 뜨는 말 중 지도에 자리가 없는 말 → 후보 목록 주 1회 승인 / 버림
길 강화 같은 채널·같은 사람이 함께 보는 토픽 → "같이" 길 후보 주 1회 승인
길 약화 사람들이 눌러 놓고 바로 나온 길 → 경고 주 1회 검토

원칙: 자동은 후보만, 확정은 사람이. 길의 이름(다음 단계인지, 같이 필요한 것인지)은 화면에 그대로 보이는 약속입니다. 그래서 사람이 확인한 길만 화면에 냅니다.

C. 재기

지표 뜻 목표 (초안)
길 따라가기 비율 영상을 본 뒤 "다음 길"을 누른 비율 25% 이상
길 만족 길을 따라간 곳에서 👍 비율 60% 이상
검색어 정확도 토픽별 상위 10 영상 중 토픽에 맞는 비율 (사람 판정) 80% 이상
뜨는 말 자리 찾기 오늘의 뜨는 말 중 지도에 자리가 있는 비율 70% 이상
세 언어 동등 한·일·영 검색어 정확도 차이 10%p 이내

5. 모드 네 개가 지도를 쓰는 법

모드 지도를 어떻게 쓰나
① 최신 트렌드 뜨는 말을 지도에 붙여 "이 말은 캠핑 > 차박의 일이에요 → 더 깊게 보기" 로 모드 ③ 에 이어 줌
② 생활 정보 토픽 버튼 = 지도의 상위·하위. 홈에 상황으로 고르기("이사 준비", "첫 캠핑") 추가 — 한 번에 여러 토픽
③ 깊이 파기 결과 아래에 깊이 사다리(입문 → 중급 → 심화)와 다음 단계 칩. 숨은 보석 점수는 "이 토픽을 잘하는 채널"과 함께 씀
④ 리저브 내 관심 토픽의 이웃 중 아직 안 가 본 곳에서 후보를 고름. "취향 밖 1편" = 관심에서 두 걸음 떨어진 토픽

화면에 생기는 것 (새로)

  • "다음 길" 칩: 영상을 다 보면 아래에 2~3개. 예: 다음 단계 › 백패킹 경량화 · 같이 › 캠핑 테이블 · 다른 방법 › 차박
  • 내 지도 (PC): 내가 다녀간 토픽을 점으로, 아직 안 간 이웃을 흐린 점으로 보여 줍니다. "내가 어디까지 왔나"가 보이는 것은 목록형 서비스에 없는 경험입니다. 휴대폰에서는 "다녀간 곳" 목록으로 줄입니다.
  • 상황 카드 (홈): "이사 준비 · 첫 캠핑 · 아기 돌 준비 · 부모님 스마트폰" — 한 번 누르면 묶인 토픽들이 펼쳐집니다. 질문 2번 규칙 안에서 됩니다.

6. 저장과 도구

  • 원본: 저장소의 ontology/*.yaml (분야별 파일). 사람이 읽고 고치기 쉽게.
  • 빌드: 검사 스크립트 통과 → 앱이 읽는 topics.json 으로 변환. 300~1,000개면 수백 KB 로 앱에 통째로 실어도 됩니다.
  • 그래프 데이터베이스는 아직 쓰지 않습니다. 토픽이 수천 개를 넘고 길 계산이 무거워지면 그때 Neo4j 같은 그래프 DB 로 옮깁니다.
  • 검수 화면: 토픽마다 세 언어 이름, 검색어로 받은 실제 영상 10개, 길 목록을 한 화면에 보여 주고 승인·고치기를 누르는 작은 내부 페이지를 만듭니다.

8. 진행 순서 (기획 v0.2 Step 과 맞춤)

기획 Step 지도 작업

Step 2 (트렌드 · 깊이 파기) 깊이 파기 200개 · 다음 단계·같이·비교 길 · 뜨는 말 연결 · 검수 화면

9. 결정 필요

  1. 첫 뼈대의 분야 — 깊이 파기 분야 15개를 무엇으로 할지. 테스트할 5명의 관심사로 정하는 것을 권합니다.
  2. 검수를 누가 하나 — 처음 10시간을 직접 하실지, 분야를 아는 지인에게 나눌지.
  3. Wikidata 연결 — 할지 (추천: 큰 토픽만), 하지 않을지.
