- 바뀐 것: 완성 그림(v0.2)은 그대로 두고, 그 앞에 **Step 0** 을 넣었습니다. 결정 9건을 확정했습니다(PM 관점 검토 반영).
- **같은 날 고침 (사용자 결정):** 처음에는 Step 0 을 「내 토픽 + 리저브」로 줄였지만, 그러면 골라봄의 차별점(이력 밖에서 고르는 세 모드)을 빼고 검증하게 됩니다. 그래서 **네 모드를 모두 Step 0 에 넣고**, 질문을 「어떤 모드가 사람을 다시 오게 하는가」로 바꿨습니다.

## 0. 쉽게 읽는 요약

**예시.** 테스터 A 씨는 평소 YouTube 홈 피드만 봅니다. 골라봄을 한 번 열어 보고 "괜찮네" 했지만, 다음 날은 습관대로 YouTube 앱을 엽니다.

**원인.** v0.2 는 화면과 기능을 자세히 설계했지만, **사람이 다시 찾아오게 만드는 계기**가 비어 있었습니다. 홈 피드만 보는 사람은 바로 그 습관 때문에 다른 사이트를 열지 않습니다. 이것이 가장 큰 위험입니다.

**바꾼 것.** 네 모드를 가벼운 판으로 모두 만들고, 2주 동안 **어떤 모드가 사람을 다시 오게 하는지** 봅니다.

- **🔥 최신 트렌드**: 인기 급상승 영상에서 쇼츠·자극적 제목·광고를 걸러 분야별로 보여 줍니다. 홈 맨 위에 한 줄.
- **내 토픽**: 첫 방문에 "관심 있는 것 고르기" 한 화면 → 고른 토픽을 누르면 영상 10편 이내.
- **🔭 깊이 파기**: 분야를 누르면 바로 **숨은 보석**(작은 채널 + 좋아요 비율 높음 + 8분 이상)이 나오고, 키워드 칩으로 좁힙니다.
- **리저브 (전문가 추천)**: 운영자가 한 사람에게 5편씩 **직접** 골라, 매주 월요일 메신저로 보냅니다. 나중에 유료로 갈 수 있는 핵심 상품입니다.

**이력을 쓰는 원칙.** 이력은 「내 토픽」의 출발점으로만 씁니다. 나머지 세 모드는 일부러 이력 밖에서 고릅니다. 이력에만 기대면 YouTube 알고리즘과 다를 게 없기 때문입니다.

**결과(판정 기준).** 5명 중 **3명 이상이 시키지 않아도 주 2회 이상** 다시 오면 다음 단계로 갑니다. 그리고 **모드별로** 다시 온 횟수를 따로 세어, 다음에 무엇을 키울지 정합니다.

**결정할 것.** 3가지입니다(§9). 테스터 5명 섭외, 방문 기록 방식, 큐레이터 표기 이름입니다.

## 3. Step 0 에서 만들 것

### A. 내 토픽 (첫 화면)

- 테스터마다 **자기 토픽 4개**가 버튼으로 보입니다. 다른 사람의 토픽은 "둘러보기"에 있습니다.
- 버튼을 누르면 **영상 5~10편**이 나옵니다. 질문은 이것 1번뿐입니다.
- 영상은 매일 새로 받아 둡니다.
  - 기본으로 빼는 것: 쇼츠(60초 이하), 제목에 광고·협찬 표시
  - 정렬: 최근 6개월 + 좋아요 비율
- 영상은 **골라봄 안에서 재생**합니다. 카드마다 👍/👎 가 있습니다.
- 결과 위 칩: `5분 · 20분 · 넉넉히` (기본 20분 안쪽)

### B. 리저브 Vol.1 · Vol.2 (수작업)

- 운영자가 테스터 **한 사람마다 5편**을 고르고, 영상마다 한 줄 코멘트를 씁니다.
- 고르는 재료: 인터뷰에서 들은 관심사와 좋아하는 영상 스타일, 그리고 내 토픽에서 누른 👍/👎
- **매주 월요일 오전**, 각자 쓰는 메신저로 **개인 링크**를 보냅니다(예: `.../#r/A/1`).
- 화면: v0.2 에서 설계한 어두운 바탕 + 금색 톤, `RESERVE Vol.1 · 숨은 명작 5편`, No.01~05, 큐레이터 서명
- 영상마다 **좋았어요 / 그저 그래요 / 안 볼래요** 를 받습니다.
- 운영 시간: 한 사람에 약 10분 × 5명 = **주 50분**

### B-2. 최신 트렌드 · 깊이 파기 (가벼운 판)

- **최신 트렌드** (`#/trend/분야`): 분야 6개(전체 · 뉴스·경제 · IT·과학 · 연예 · 스포츠 · 생활)의 인기 급상승 영상에서 쇼츠, 자극적 제목(충격·레전드 등), 광고를 빼고 10편. 홈 맨 위에 6편을 한 줄로 보여 줍니다.
- **깊이 파기** (`#/d/분야`): 분야 5개(캠핑 · 커피 · 사진 · 통기타 · 요리) × 키워드 6개. 분야를 누르면 바로 분야 전체의 보석 영상이 나오고(질문 1), 키워드 칩으로 좁힙니다(질문 2).
  - 숨은 보석 점수 = 좋아요 비율 + 구독자 1천~10만 채널 우대 + 20분 이상 가산. 최근 2년 · 8분 이상만.
  - 카드에 `💎 구독자 8천 · 좋아요 비율 상위 5% · 24분` 처럼 이유를 붙입니다.
- 분야와 키워드는 `app/data/topics.json` 에서 고칩니다. 테스터 인터뷰 뒤 관심사에 맞춰 바꿉니다.

### C. 화면과 디자인

- **휴대폰 우선**으로 만듭니다. PC 에서는 같은 화면을 넓게만 보여 줍니다.
- 디자인은 **두 화면(내 토픽, 리저브)에 필요한 것만** 정하고 공들입니다: 색, 글자 크기 4단계, 간격 규칙, 영상 카드 하나.
- 웹앱 기본은 넣습니다: 홈 화면에 추가할 수 있게(`manifest.json`, 아이콘).
- 비밀번호 문은 지금처럼 둡니다. 다만 이것은 **화면에서만 막는 장치라 보안 기능이 아닙니다.**

## 5. 기술 구조

### 영상 데이터: 저장소에 커밋하지 않습니다

**YouTube API 정책상, API 로 받은 데이터는 원칙적으로 30일 넘게 보관할 수 없습니다.** 그 전에 지우거나 새로 받아야 합니다. 구독자 수 같은 통계값도 마찬가지입니다. 공개 저장소에 커밋하면 git 기록에 영원히 남으므로 이 규정에 걸립니다.

그래서 이렇게 합니다.

1. GitHub Actions 가 **매일 새벽** API 로 영상을 받아 `data/*.json` 을 만듭니다.
2. 이 파일을 **커밋하지 않고**, 사이트 파일과 함께 **Pages 배포본으로만** 올립니다. 매일 새 배포가 이전 것을 대체하므로 오래된 데이터가 남지 않습니다.
3. 리저브에 고른 영상은 **영상 ID 와 운영자 코멘트만** 저장소에 둡니다. 제목, 썸네일, 길이 같은 정보는 매일 자동 작업이 새로 받아 붙입니다.

※ 이 판단은 정책 안내문 요약에 근거합니다. 착수 첫날 [정책 원문](https://developers.google.com/youtube/terms/developer-policies)을 읽고 확정합니다.

### API 사용량

- 내 토픽 20개 × 검색 1번(100단위) = **약 2,000단위**
- 깊이 파기 키워드 30개 × 검색 1번 = **약 3,000단위** (+ 채널 구독자 수 조회, 50개당 1단위)
- 최신 트렌드 분야 6개 × 인기 급상승 1단위 = **6단위**
- 합계 **하루 약 5,100단위**, 무료 한도 10,000단위의 절반입니다.

### 방문 기록 (재방문을 재기 위해)

- 테스터마다 **코드(A~E)가 붙은 개인 링크**를 줍니다. 이름은 저장하지 않습니다.
- 방문, 재생, 👍/👎, 리저브 반응을 **쿠키를 쓰지 않는 무료 방문 통계 도구**로 기록합니다(예: GoatCounter, §9 결정).
- 브라우저 저장(`localStorage`)은 화면 편의용으로만 씁니다. 측정은 이것에 기대지 않습니다.

- **통과** → Step 1: v0.2 의 생활 정보를 정식으로 만들고, 리저브에 AI 후보를 더합니다.

## 9. 결정 필요 (3가지)

1. **테스터 5명** — 누구를 섭외할지. 다양하면 좋습니다(나이대, 휴대폰과 PC, 관심사).
2. **방문 기록 방식** — GoatCounter 같은 무료 방문 통계 도구를 쓸지 *(추천: 쓴다 · 쿠키 없음 · 이름 저장 없음)*. 쓰지 않으면 재방문을 잴 방법이 없습니다.
3. **큐레이터 표기** — 리저브 서명에 쓸 이름. 예: "큐레이터 김" 또는 닉네임. 실제 운영자 본인이어야 합니다.

## 부록 A. 테스터 인터뷰 질문지 (15분)

**원칙**
- 이름, 나이, 직업 같은 개인정보는 묻지 않습니다. 테스터는 코드(A~E)로만 기록합니다.
- 기록은 저장소 밖에 둡니다.
- 답을 유도하지 않고, 실제로 했던 일을 묻습니다.

**질문**

1. 요즘 YouTube 는 주로 **언제, 무엇으로** 보세요? (휴대폰 / PC / TV, 하루 대략 얼마나)
2. 지난 일주일 동안 본 영상 중 **기억나는 것 2~3개**는요? 그 영상은 어떻게 보게 됐나요? (홈 추천 / 검색 / 누가 보내 줌)
3. 최근에 **검색창에 무언가를 쳐 본 적** 있으세요? 뭐라고 쳤고, 원하는 걸 찾았나요?
4. YouTube 를 보다가 **짜증 났던 순간**이 있다면요? (쇼츠, 광고, 낚시 제목, 계속 같은 것만 …)
5. 요즘 **알아보고 싶거나 관심 가는 것** 4가지만 꼽아 주세요. (살 것, 배우고 싶은 것, 취미, 그냥 궁금한 것) → **내 토픽 4개**
6. 좋아하는 영상 **스타일**은요? 짧게 vs 길게, 차분한 설명 vs 신나는 분위기, 전문가 vs 나 같은 일반인, 외국어 영상(자막)도 괜찮은지 → **리저브 고를 때 참고**
7. 테스트 기간 동안 **매주 월요일 아침 링크를 받아도** 괜찮으세요? 어느 메신저가 편하세요?
8. 테스트 동안 주로 쓸 기기는요? (아이폰 / 안드로이드 / PC)

**마지막 날 질문 (1개):** "지난 2주, 영상을 찾고 볼 때 골라봄이 YouTube 홈보다 나았나요?" 예 / 아니오 + 한 줄 이유

## 부록 B. YouTube API 키 발급 순서 (운영자가 직접)

키는 **채팅에 붙여 넣지 마시고**, 아래 마지막 단계에서 GitHub 에 직접 등록해 주세요.

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에 로그인합니다.
2. 위쪽의 프로젝트 선택 → **새 프로젝트** → 이름 `golabom` → 만들기
3. 왼쪽 메뉴 **API 및 서비스 → 라이브러리** → "YouTube Data API v3" 검색 → **사용**
4. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키**
5. 만들어진 키의 **키 제한**:
   - API 제한: **YouTube Data API v3 만** 허용
   - 애플리케이션 제한: 없음 (GitHub Actions 서버에서만 쓰기 때문)
6. GitHub 의 `Vinni-tokyo/golabom` → **Settings → Secrets and variables → Actions → New repository secret**
   - 이름: `YT_API_KEY`
   - 값: 위에서 만든 키
7. 등록했다고 알려 주시면, 자동 작업을 만들어 한 번 시험으로 돌려 보겠습니다.

※ 무료 한도는 하루 10,000단위이고, 결제 수단을 등록하지 않아도 됩니다. 한도를 넘으면 그날만 멈추고, 요금이 나가지는 않습니다.
