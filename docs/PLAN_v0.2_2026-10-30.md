## 0. 쉽게 읽는 요약

**예시.** 매일 YouTube 홈에 뜨는 영상만 보는 사람이 있습니다. 요즘 캠핑 의자를 사고 싶은데, 검색창에 뭐라고 쳐야 할지 모릅니다. 쳐 봐도 쇼츠와 광고 영상만 나옵니다.

**원인.** 이 사람은 원하는 게 있지만 검색어로 옮기지 못합니다. 그래서 알고리즘이 주는 것만 보게 됩니다. Phase 0 은 이 사람에게 맞지 않았습니다. 검색어를 화면에 그대로 보여 줬고, 결과도 영상이 아니라 링크 10개였습니다.

**바꾼 것.** 목적에 따라 들어가는 길을 네 갈래로 나눴습니다.

| 모드 | 이런 때 | 들어가는 법 |
|---|---|---|
| **① 최신 트렌드** | 요즘 무슨 얘기가 도는지 알고 싶을 때 | 분야 1번(건너뛰어도 됨) → 뜨는 말 → **핵심을 설명하는 영상** |
| **② 생활 정보** | 살 것·할 것을 빨리 알아볼 때 | 토픽 버튼 2번 → 영상 |
| **③ 깊이 파기** | 좋아하는 분야를 제대로 파고들 때 | 분야 → 요즘 뜨는 키워드 → **숨은 보석 영상** |
| **④ 골라봄 리저브** | 뭘 볼지 모를 때 | 관심 분야 → 끌리는 썸네일 고르기 → 매주 **큐레이터가 고른, 쉽게 못 찾는 5편** |

네 모드 모두 **글자를 쓰지 않아도 되고, 두 번만 물으면 영상이 나옵니다.** 더 좁히고 싶은 사람만 결과 화면에서 칩을 눌러 고칩니다. 결과는 링크가 아니라 **영상 10개 이내**이고, 골라봄 안에서 바로 재생합니다.

**결과(기대).** 같은 추천만 보던 사람이 버튼 몇 번으로 자기가 원하던 영상에 닿습니다. 모드마다 "그냥 YouTube 보다 나았나"를 따로 잽니다(§10).

**만드는 형태.** 하나의 웹앱으로 **모바일 웹앱과 PC 웹앱**을 함께 만듭니다. 휴대폰은 홈 화면에 추가, PC 는 앱 설치로 앱처럼 씁니다(§7-2).

**결정할 것.** 6가지입니다(§11). 가장 중요한 것은 **모드 ④ 리저브의 "큐레이터"를 실제 사람으로 할지**입니다.

## 1. 누구를 위한 서비스인가

**한 줄 취지**

> 같은 추천 영상만 보던 사람이, 글자를 쓰지 않고 버튼만으로, 자기가 정말 원하는 영상을 골라 보게 한다.

**대상: 일반 YouTube 사용자**

- 검색창을 거의 쓰지 않습니다. 홈 화면과 "다음 영상"으로 봅니다.
- 원하는 것을 단어로 바로 떠올리지 못하지만, **보기를 보여 주면 고를 수 있습니다.**
- 쇼츠, 자극적인 제목, 광고 영상에 지쳐 있지만 피하는 방법을 모릅니다.

**대상이 아닌 사람**

- 검색어를 잘 쓰는 사람. 이분들은 YouTube 공식 고급 필터(2026년 1월부터 쇼츠 빼기 가능)로 충분합니다.

**설계 원칙 5가지**

1. **키보드를 쓰지 않는다.** 직접 쓰기 칸은 남겨 두되 맨 아래에 작게 둡니다.
2. **검색어를 보여 주지 않는다.** 검색어는 뒤에서 만들고, 화면에는 고른 조건만 쉬운 말로 보여 줍니다.
3. **결과는 영상 10개 이내.** 개수는 5개나 10개로 고를 수 있습니다.
4. **골라봄 안에서 재생한다.** YouTube 옆의 추천 목록으로 다시 끌려가지 않게 합니다.
5. **두 번 묻고, 세 번째에는 영상을 보여 준다.** 질문이 3번을 넘으면 영상을 고르기도 전에 지칩니다. 나머지 조건은 미리 정한 기본값으로 채우고, 결과 화면 위의 칩으로 **나중에** 고치게 합니다. 묻는 대신 반응(👍/👎, 좋았어요)에서 배웁니다.

## 2. 모드 4개 한눈에

| | ① 최신 트렌드 | ② 생활 정보 | ③ 깊이 파기 | ④ 골라봄 리저브 |
|---|---|---|---|---|
| **묻는 것 (최대 2번)** | 분야(선택) · 뜨는 말 | 대분류 · 소분류 | 분야 · 뜨는 키워드 | 관심 분야 · 끌리는 썸네일 |
| **결과 화면에서 고치는 것** | 시간 · 다른 관점 보기 | 시간 · 개수 | 깊이 · 종류 · 언어 · 빼기 | 취향 카드 막대 |
| **첫 영상까지 누르는 횟수** | 1~2번 | 2번 | 2번 (키워드 건너뛰면 1번) | 처음 2번 → 다음부터 0번 |
| **결과** | 뜨는 말 하나당 설명 영상 3~5개 | 최신·실용 영상 5~10개 | 숨은 보석 영상 5~10개 | 이번 호 5편 + 큐레이터 코멘트 |
| **누가 고르나** | 뜨는 말은 매일 자동 작업, 영상은 설명 점수 | 사용자가 토픽을 고르고, 정렬은 규칙이 | 사용자 + 보석 점수 | 골라봄(AI 후보 → 사람 확정) |
| **알고리즘과 다른 점** | 자극적 반응 영상 대신 무슨 일인지 설명하는 영상 | 내가 고른 토픽만 나온다 | 구독자 적은 좋은 채널이 위로 온다 | 내 취향을 사람이 읽고 고른다 |
| **영상 데이터** | 하루 2번 미리 받아 둠 | 매일 미리 받아 둠(배치) | 트렌드는 배치, 검색은 실시간 | 매주 미리 골라 둠 |

**홈 화면**에는 맨 위에 **오늘의 뜨는 말** 한 줄, 그 아래 모드 카드 3장과 **"지난번처럼"** 버튼을 둡니다. 두 번째 방문부터는 1번만 누르면 됩니다.

## 3. 모드 ① 최신 트렌드

**목적:** 요즘 사람들이 무슨 얘기를 하는지, **추천 피드에 휩쓸리지 않고** 짧고 정확하게 알게 합니다. 생활 정보보다 위에 둡니다. 홈을 열면 가장 먼저 보이는 모드입니다.

### 흐름 (1~2번)

1. **분야** (선택) — 전체 · 사회·경제 · IT·테크 · 연예·문화 · 스포츠 · 생활·소비. 고르지 않으면 "전체"입니다.
2. **오늘의 뜨는 말** — 10개 안팎. 말마다 **"왜 뜨나" 한 줄**이 붙어 있습니다. 하나를 누르면
→ **그 일을 설명하는 영상 3~5개.**

- 홈 맨 위에 "오늘의 뜨는 말" 다섯 개가 한 줄로 보입니다. 거기서 바로 누르면 **1번**에 영상이 나옵니다.

### 모드 ③(깊이 파기)의 트렌드 키워드와 다른 점

| | ① 최신 트렌드 | ③ 깊이 파기의 뜨는 말 |
|---|---|---|
| 범위 | 사회 전체의 화제 | 내가 고른 취미·지식 분야 안 |
| 목적 | 무슨 일인지 **빨리 알기** | 그 분야를 **깊게 파기** |
| 영상 | 짧은 설명 영상 위주(5~15분) | 긴 실험·비교·다큐도 포함 |
| 갱신 | 하루 2번(아침·저녁) | 하루 1번 |

### 뜨는 말 만드는 법 (자동 작업, 하루 2번)

1. **YouTube 인기 급상승 영상**(한국·일본, 분야별)을 받습니다. API 로 1단위면 되어서 거의 공짜입니다.
2. **Google 일별 인기 검색어**(공개 RSS)를 보조로 받습니다. *⚠️ 제공 형식이 바뀔 수 있어 착수 때 확인합니다.*
3. 둘을 합쳐 자주 나온 말을 고르고, LLM 이 **"왜 뜨나" 한 줄**을 씁니다. 근거가 된 영상 제목을 같이 저장합니다.
4. `trends_today.json` 으로 저장합니다.

### 설명 영상을 고르는 기준

- **설명하는 영상**을 우선합니다: 제목·설명에 "정리 · 무슨 일 · 이유 · 해설 · 뉴스" 같은 말, 자막, 5~15분.
- **기본으로 빼는 것**: 쇼츠, 리액션, 자극적 제목, 짜깁기.
- **출처를 보여 줍니다**: 카드에 채널 종류(방송사 · 전문 채널 · 개인)를 붙입니다.
- **다른 관점 보기**: 의견이 갈리는 말(정치·사회)은 결과 아래에 "다른 관점" 칩을 둡니다. 한쪽 영상만 나오지 않게 합니다. Phase 0 의 "다른 관점" 카드를 이어받습니다.

### 주의할 점

- **"왜 뜨나" 한 줄은 AI 가 쓴 요약입니다.** 틀릴 수 있으므로 화면에 "AI 요약"이라고 표시하고, 근거 영상을 바로 볼 수 있게 합니다.
- 사건·사고, 건강 정보처럼 틀리면 해가 되는 말은 요약을 쓰지 않고 영상만 보여 주는 것을 기본으로 합니다.

## 4. 모드 ② 생활 정보

**목적:** 알고리즘이 정해 주는 대신 **내가 고른 토픽**으로 실용 정보를 빠르게 모읍니다.

### 흐름

1. **대분류** (큰 버튼 8개) → 2. **소분류** (칩 6~10개) → **바로 영상 목록**

- 시간은 묻지 않습니다. 기본값은 "20분 안쪽"이고, 결과 위의 칩(`5분 · 20분 · 넉넉해요`)으로 바꿉니다.
- 두 번째부터는 홈의 "지난번처럼"이나 "내 토픽"으로 **1번**이면 됩니다.

### 토픽 트리 (초안 · 확정 필요)

| 대분류 | 소분류 예 |
|---|---|
| 🍳 먹고 살기 | 10분 집밥 · 도시락 · 장보기 · 보관법 · 다이어트 식단 |
| 🏠 집·살림 | 청소 · 수납 · 셀프 수리 · 이사 · 인테리어 |
| 💰 돈 | 절약 · 연말정산 · 보험 · 카드 혜택 · 재테크 기초 |
| 🩺 건강 | 스트레칭 · 수면 · 허리·목 · 걷기 · 병원 가기 전 |
| 🛒 살 것 알아보기 | 가전 · 스마트폰 · 캠핑 용품 · 육아 용품 · 자동차 |
| 📱 기기·앱 | 스마트폰 설정 · 사진 정리 · 무료 앱 · 보안 |
| ✈️ 나들이·여행 | 근교 · 국내 · 일본 · 준비물 · 교통 |
| 🐶 가족·반려 | 육아 · 반려견 · 반려묘 · 부모님 |

### 내 토픽

- 결과 화면의 ☆ 를 누르면 **내 토픽**에 저장됩니다.
- 홈의 "내 토픽 새 영상"을 누르면 저장한 토픽의 **최근 영상만** 모아서 보여 줍니다.
- 알고리즘이 고른 피드가 아니라 **내가 고른 토픽 피드**입니다. 이것이 모드 ②의 핵심입니다.

### 정렬 규칙

- 최근 6개월 이내 영상을 우선합니다. 생활 정보는 오래되면 틀리기 쉽습니다.
- 쇼츠는 기본으로 뺍니다(길이 60초 이하 제외).
- 제목에 "광고·협찬·#ad" 가 있거나 유료 광고 표시가 있으면 기본으로 뺍니다.
- 조회수만으로 줄 세우지 않습니다. 대신 **좋아요÷조회수**를 함께 봅니다.

### 비용

토픽이 정해져 있으므로 **매일 한 번 미리 받아 둡니다.** 사용자가 아무리 많이 눌러도 API 를 쓰지 않습니다(§8).

## 5. 모드 ③ 깊이 파기

**목적:** 좋아하는 분야를 깊게 파는 사람에게, 알고리즘이 잘 보여 주지 않는 **숨은 보석 영상**을 찾아 줍니다.

### 흐름 (2번 묻고 바로 결과)

1. **분야** — 모드 ②보다 넓은 취미·지식 분야 (예: 캠핑, 기타, 역사, 사진, 커피, 투자, AI …)
2. **요즘 뜨는 키워드** — 그 분야에서 이번 주에 뜨는 키워드 칩 8~12개 *(아래 참고)* · "분야 전체"로 건너뛸 수 있음

→ **바로 보석 영상 목록.** "세밀한 입력"은 질문으로 받지 않고, **결과 화면 위의 칩 줄**로 받습니다. 누를 때마다 결과가 바뀝니다.

| 칩 줄 | 보기 | 기본값 |
|---|---|---|
| 깊이 | 처음 · 어느 정도 · 깊게 | 어느 정도 |
| 영상 종류 | 설명 · 리뷰 · 비교 · 실험 · 인터뷰 · 다큐 · 풀버전 | 전체 |
| 언어 | 한국어 · 영어(자막) · 일본어(자막) | 한국어 + 자막 있는 외국어 |
| 빼기 | 쇼츠 · 리액션 · 짜깁기 · 자극적 제목 · 광고 | 쇼츠 · 광고 |

- 사용자가 바꾼 칩은 기억해 두었다가 다음에도 기본값으로 씁니다.

결과 위에는 고른 조건을 **문장으로** 보여 줍니다.

> **캠핑** 중 **「동계 차박」**을, **어느 정도 아는** 사람용 **실험·비교** 영상으로. **쇼츠·광고** 빼고.

단어를 누르면 그 조건만 바로 바꿀 수 있습니다.

### 요즘 뜨는 키워드: 우리가 매일 찾아서 제시

**만드는 법 (매일 1번, 자동 작업)**

1. 분야마다 최근 7일 동안 올라온 영상 중 조회수 상위 50개를 받습니다(YouTube Data API).
2. 제목과 태그에서 **지난주보다 자주 나온 말**을 뽑습니다.
3. LLM 이 비슷한 말을 묶고, 쉬운 말로 다듬고, 한·영·일로 맞춥니다. 예: "동계 차박", "winter car camping", "冬の車中泊"
4. 결과를 `trends.json` 으로 저장하면 사이트가 읽습니다.

**보조 자료:** Google Trends 는 공식 API 가 없습니다. 그래서 주 1회 사람이 확인하는 참고 자료로만 씁니다.

**칩 표시:** 🔥 이번 주 급상승 / 📈 꾸준히 상승 / 🆕 새로 등장

### 숨은 보석 점수

"좋은데 덜 알려진 영상"을 숫자로 정합니다. 초안이며, 테스트로 조정합니다.

| 신호 | 의미 | 방향 |
|---|---|---|
| 좋아요 ÷ 조회수 | 본 사람이 만족했나 | 높을수록 + |
| 댓글 ÷ 조회수 | 이야기할 거리가 있나 | 높을수록 + |
| 채널 구독자 수 | 알고리즘이 이미 밀어주나 | **적을수록 +** (1천~10만 구간 우대) |
| 길이 | 내용이 충분한가 | 8분 이상 + |
| 올린 시기 | 너무 오래되진 않았나 | 최근 2년 + |

- 결과 카드에는 **💎 보석인 이유**를 한 줄 붙입니다. 예: `구독자 8천 채널 · 좋아요 비율 상위 5% · 24분 실험`
- 조회수 100 미만은 뺍니다. 표본이 적어 비율이 흔들립니다.

### Phase 0 의 링크 생성기는 이곳으로

지금의 링크 생성 기능(검색어 조립, `sp=` 필터, Google 정밀 검색)은 지우지 않습니다. 모드 ③ 결과 맨 아래 **"YouTube 에서 직접 더 보기"**로 옮깁니다.

## 6. 모드 ④ 골라봄 리저브 (가칭) — 큐레이터가 고른 이번 주 5편

**목적:** 뭘 볼지 모르는 사람에게, 그 사람의 성향을 읽고 **알고리즘이 보여 주지 않았을 영상**을 골라 줍니다.

### 이름과 느낌: "쉽게 찾을 수 없는 것을, 나만 받는다"

"이번 주 골라봄"은 이름이 약합니다. 이 모드는 **전문가가 고른, 아무나 못 찾는 영상**이라는 느낌을 줘야 합니다.

- **이름 후보** (§11 결정): **골라봄 리저브** *(작업명)* · 큐레이터스 컷 · 골라봄 프라이빗 · 숨은 명작 5
- **호수를 붙인 발행물처럼**: `RESERVE · Vol.12 · 10월 5주` — 잡지나 와인 리스트처럼 매주 한 호씩 나옵니다.
- **딱 5편, 일주일만**: "다음 호는 월요일 오전 7시" — 지나간 호는 보관함으로 갑니다. 희소성이 가치를 만듭니다.
- **번호와 서명**: 영상마다 `No.01` ~ `No.05`, 끝에 큐레이터 이름과 한 줄 서명을 붙입니다.
- **왜 쉽게 못 찾는지 밝히기**: `구독자 3천 채널` · `일본어 원작(한국어 자막)` · `조회수 4천, 좋아요 비율 상위 2%` — 알고리즘이 위로 올려 주지 않는 이유를 숫자로 보여 줍니다.
- **화면 톤**: 다른 모드와 구별되게 어두운 바탕 + 금색 포인트, 넉넉한 여백, 큰 썸네일. 실제 색과 글꼴은 디자인 단계에서 정합니다.
- **⚠️ 정직하게**: "전문가 · 큐레이터" 라는 말은 **사람이 실제로 고를 때만** 씁니다(§6-6). 문구를 그럴듯하게 만들려고 없는 전문가를 내세우지 않습니다.

### 6-1. 관심 분야 묻기 (처음 1번 · 질문 1)

- "요즘 관심 가는 것을 모두 골라 주세요." 칩을 여러 개 고를 수 있습니다(모드 ②·③의 분야를 합친 목록).
- 3개 이상 고르면 다음으로 넘어갑니다.

### 6-2. 취향 진단: "끌리는 영상을 모두 눌러 주세요" 한 화면 (질문 2)

8판을 하나씩 묻지 않습니다. **썸네일 9장을 한 화면에** 보여 주고, 끌리는 것을 모두 누르게 합니다. 9장은 관심 분야 안에서 성향 축이 서로 다르게 미리 골라 둔 영상입니다. 어떤 것을 눌렀는지로 여러 축을 한 번에 읽습니다.

- 예: 5분 요약 / 40분 풀버전 / 말 없이 보여 주기 / 전문가 강의 / 일반인 브이로그 / 외국어(자막) / 처음 보는 주제 …
- 하나도 안 끌리면 "다른 9장 보기"를 누릅니다. 질문 수에는 세지 않습니다.
- 끝나면 바로 **이번 호 5편**이 나옵니다. 처음 오는 사람에게도 2번이면 영상이 보입니다.

**나머지는 묻지 않고 반응에서 배웁니다.** 진단 한 화면으로 정확하지 않은 축은 매주 반응(좋았어요/별로)으로 채웁니다. 한 주에 한 번, 5편 아래에 **질문 하나**만 덧붙일 수 있습니다(예: "이번 주는 짧은 게 좋아요, 긴 게 좋아요?"). 답하지 않아도 됩니다.

읽어 내려는 성향 축은 아래 8개입니다.

| 축 | 왼쪽 | 오른쪽 |
|---|---|---|
| 길이·깊이 | 핵심만 5분 | 처음부터 끝까지 40분 |
| 분위기 | 차분한 설명 | 신나는 에너지 |
| 말하는 사람 | 전문가 | 나 같은 일반인 |
| 보여 주는 방식 | 말로 설명 | 말 없이 보여 주기 |
| 새로움 | 익숙한 주제 깊게 | 처음 보는 주제 |
| 화면 | 깔끔한 편집 | 날것 그대로 |
| 이야기 | 정보 위주 | 사람 이야기 위주 |
| 언어 | 한국어만 | 외국어도 자막이면 OK |

- 9장으로 읽지 못한 축은 중간값으로 두고, 반응이 쌓이면 고칩니다.

### 6-3. 내 취향 카드

진단이 끝나면 한 장짜리 카드를 보여 줍니다.

> **차분하게 깊이 파는 탐구형**
> 긴 영상 ●●●●○ · 차분함 ●●●●○ · 전문가 ●●●○○ · 새로움 ●●○○○
> 관심: 캠핑 · 커피 · 역사

- 카드는 언제든 다시 진단하거나, 막대를 직접 움직여 고칠 수 있습니다.
- 이 카드가 **골라봄이 나를 어떻게 이해했는지** 보여 주는 투명성 장치입니다.

### 6-4. 이번 호 5편 (RESERVE Vol.N)

- **매주 월요일**, 5편만 나옵니다. 10편보다 적게 주는 것이 "골라 준다"는 신뢰를 만듭니다.
- 카드마다 붙는 것:
  - **고른 이유 한 줄** (큐레이터 코멘트) — "차분한 설명을 좋아하셔서, 말없이 커피를 내리는 25분 영상을 골랐어요."
  - **알고리즘이 안 보여 줬을 이유** — `구독자 3천 채널` · `일본어 영상(한국어 자막)` · `3년 전 영상이지만 지금도 유효`
- 5편 중 1편은 **"취향 밖 1편"**입니다. 새로움 축이 낮은 사람에게도 일부러 하나를 섞습니다. 같은 것만 보는 문제를 정면으로 다룹니다.

### 6-5. 반응과 다음 주

- 영상마다 버튼 3개: **좋았어요 / 그저 그래요 / 안 볼래요**
- 반응은 다음 주 선택에 반영합니다. 어떻게 반영했는지도 알려 줍니다. 예: "지난주 '말 없이 보여 주기'를 좋아하셔서 이번 주에 2편 넣었어요."
- 5편을 다 보면 "더 받기"로 모드 ③ 결과를 이어서 보여 줍니다.

### 6-6. "전문가 그룹"은 어떻게 운영하나 — 결정 필요

**제안: AI 가 후보를 고르고, 사람이 확정한다.**

1. AI 가 취향 카드와 관심 분야를 보고, 보석 점수(§5)가 높은 영상 중에서 **후보 20~30편**을 고릅니다.
2. **사람 큐레이터**가 후보를 보고 **5편을 확정**하고 한 줄 코멘트를 씁니다.
3. 테스트 단계(5명)에서는 운영자가 직접 큐레이터를 맡을 수 있습니다. 1인당 주 10분 정도입니다.

**지켜야 할 것:** 사람이 실제로 고르지 않는다면 화면에 "전문가 그룹"이라고 쓰면 안 됩니다. 사용자를 속이는 것이 되기 때문입니다. AI 만으로 운영한다면 이름을 **"골라봄 AI 추천"**으로 바꿉니다.

### 6-7. "알고리즘을 뛰어넘는다"를 어떻게 확인하나

- **블라인드 비교:** 같은 사람에게 YouTube 홈 상위 5편과 골라봄 5편을 섞어서, 출처를 가리고 보여 줍니다. "보고 싶은 것"을 고르게 합니다.
- **기준:** 골라봄 쪽을 고른 비율이 **60% 이상**이면 "뛰어넘는다"고 말할 수 있습니다.

## 7-1. PC 화면 설계

**원칙: 같은 흐름, 한 화면에 펼치기.** 휴대폰은 한 단계씩 넘기지만, PC 는 화면이 넓으므로 **조건과 결과를 한 화면에** 둡니다. 조건을 누르면 결과가 그 자리에서 바로 바뀝니다. 모드 구조와 묻는 것은 휴대폰과 같습니다.

| 화면 | 휴대폰 | PC |
|---|---|---|
| **홈** | 맨 위 오늘의 뜨는 말 한 줄 + 모드 카드 세로 3장 | 맨 위 오늘의 뜨는 말 + 모드 카드 가로 3장 + 아래에 "지난번처럼"과 내 토픽 새 영상 한 줄 |
| **① 최신 트렌드** | 분야 칩 → 뜨는 말 목록 → 영상 | **왼쪽 뜨는 말 순위**(왜 뜨나 한 줄) · 누르면 오른쪽에 설명 영상 + 다른 관점 |
| **② 생활 정보** | 대분류 → 소분류, 2장 넘기기 | **두 칸에 한 번에 펼침**(파일 탐색기의 열 보기처럼) + 시간 칩 · 아래에 결과 5열 |
| **③ 깊이 파기** | 분야 → 키워드 2장 → 결과 위 칩 줄 | **왼쪽 조건판 고정**(250px, 위 2개는 질문 · 아래는 결과 고치기 칩) · 오른쪽 위 조건 문장 · 그 아래 플레이어 + 대기열 |
| **④ 골라봄 리저브** | 어두운 바탕, No.01~05 한 편씩 넘기기 | **잡지형**: 큰 1편 + 작은 4편 · 오른쪽에 취향 카드와 "지난주 반영" |
| **재생** | 카드 누르면 전체 화면 | 결과 옆에서 재생 · **대기열 = 내 결과 10개**(YouTube 추천 아님) |

**PC 에서만 더하는 것**

- **단축키:** 결과에서는 `J` / `K` 로 이전·다음 영상, `Space` 로 재생, `+` / `−` 로 이런 것 더 / 이건 빼를 누릅니다. 화면에 작게 안내합니다.
- **상단 탭:** 홈 · 최신 트렌드 · 생활 정보 · 깊이 파기 · 리저브를 언제든 오갈 수 있습니다. 휴대폰은 홈으로 돌아가서 고릅니다.
- **마우스를 올리면** 영상 카드에 고른 이유 전체와 채널 정보를 보여 줍니다(휴대폰은 한 줄만).

**화면 폭에 따른 배치**

| 폭 | 배치 |
|---|---|
| 1200px 이상 | 조건판 + 결과 5열(모드 ②) / 조건판 + 플레이어 + 대기열(모드 ③) |
| 960~1200px | 결과 3열 · 대기열은 플레이어 아래로 |
| 960px 미만 | 휴대폰 화면(단계식)으로 바꿈 |

## 7-2. 만드는 형태: 모바일 웹앱 + PC 웹앱

**하나의 웹앱으로 휴대폰과 PC 를 모두 지원합니다.** 앱스토어에는 올리지 않습니다. 화면 폭에 따라 §7-1 의 배치로 자동으로 바뀝니다.

| | 모바일 웹앱 | PC 웹앱 |
|---|---|---|
| **여는 법** | 주소로 열기 → **홈 화면에 추가** | 주소로 열기 → Chrome·Edge 의 **앱 설치** |
| **설치하면** | 아이콘이 생기고, 주소창 없이 전체 화면으로 열림 | 따로 된 앱 창으로 열리고, 작업 표시줄에 고정 가능 |
| **화면** | 단계식 · 아래쪽 탭 막대(홈 · 트렌드 · 생활 · 깊이 · 리저브) | 위쪽 탭 · 조건판 + 결과 + 플레이어를 한 화면에 |
| **조작** | 큰 버튼 · 엄지로 닿는 아래쪽에 주요 버튼 | 마우스 + 단축키 |
| **재생** | 골라봄 안에서 재생(YouTube 공식 플레이어) | 같음 · 대기열 = 내 결과 |

**공통 기술 (PWA)**

- `manifest.json`: 앱 이름, 아이콘, 테마 색을 정합니다. 이것이 있어야 "홈 화면에 추가"와 "앱 설치"가 됩니다.
- **서비스 워커**: 마지막 결과, 내 토픽, 취향 카드를 저장해 두어 **다시 열 때 바로 뜹니다.** 영상 재생은 인터넷이 있어야 합니다.
- **배포**: 지금처럼 GitHub Pages 에 올립니다. 서버는 Worker(§8) 하나뿐입니다.
- **비밀번호 문**: 테스트 단계에서는 그대로 둡니다.
- **알림(나중에)**: 모드 ④ 리저브의 "새 호 도착" 알림은 웹 푸시로 할 수 있습니다. 아이폰은 iOS 16.4 이상에서 홈 화면에 추가한 경우에만 됩니다. Step 4 에서 다룹니다.

**코드 구조:** Phase 0 은 `index.html` 하나였습니다. 웹앱은 화면이 늘어나므로 파일을 나눕니다(화면별 모듈 · 공통 영상 카드 · 데이터 읽기). 빌드 도구를 쓸지는 Step 1 착수 때 정합니다.

**디자인:** 위 목업은 배치 확인용입니다. 색, 글꼴, 여백, 움직임, 아이콘은 Step 1 개발 때 **디자인 시스템(색·글자 크기·간격 규칙)부터 정하고** 공들여 만듭니다.

## 8. 기술 구조: 미리 받아 두기가 기본

**왜 미리 받아 두나.** YouTube Data API 무료 한도는 하루 10,000단위이고, 검색 1번에 100단위가 듭니다. 사용자가 누를 때마다 검색하면 **하루 약 100번**으로 끝납니다.

| 부분 | 방식 | 하루 사용량 (추정) |
|---|---|---|
| 모드 ① 뜨는 말 | 하루 2번 자동 작업(인기 급상승 + 인기 검색어 + LLM 한 줄) → `trends_today.json` | 인기 급상승 1단위 + 뜨는 말별 설명 영상 검색 10개 × 100 × 2회 = **2,000** |
| 모드 ② 토픽 영상 | 매일 1번 자동 작업 → `topics/*.json` | 소분류 40개 × 100 = **4,000** |
| 모드 ③ 트렌드 키워드 | 매일 1번 자동 작업 → `trends.json` | 분야 15개 × 100 = **1,500** |
| 모드 ③ 실시간 검색 | Cloudflare Worker 가 키를 숨기고 대신 검색 | 남는 ~2,000 → **약 20번/일** |
| 모드 ④ 후보 | 주 1번 자동 작업 + 사람 확정 → `picks/*.json` | 주 1회 · 하루 평균 소량 |
| 영상 상세(길이·좋아요) | `videos.list` (50개당 1단위) | 무시할 수준 |

- **자동 작업:** GitHub Actions 로 돌립니다. 결과 JSON 은 저장소에 커밋되고 Pages 가 그대로 서비스합니다. 서버가 필요 없습니다.
- **한도 늘리기:** 실제 사용자가 생기면 Google 에 한도 증설을 신청해야 합니다. 신청은 무료이지만 심사가 있습니다.
- **⚠️ 확인 필요:** YouTube API 이용 정책에는 받아 둔 데이터를 오래 보관하는 것에 대한 제한이 있습니다. 매일 새로 받으므로 문제없을 것으로 보지만, 착수 전에 정책 원문을 확인합니다.

## 9. 단계별 진행

| 단계 | 만드는 것 | 검증 |
|---|---|---|
| **Step 1** | 디자인 시스템 · 웹앱 뼈대(모바일 + PC, 홈 화면 추가·앱 설치) · 홈 · 모드 ② (토픽 트리 + 매일 자동 작업) · 공통 영상 카드 · 앱 안 재생 | 5명이 휴대폰과 PC 에서 각자 토픽 3개로 써 본다 |
| **Step 2** | 모드 ① 최신 트렌드 + 모드 ③ 깊이 파기 (같은 트렌드 자동 작업을 함께 씀 · 보석 점수 · Worker 실시간 검색) | 뜨는 말 "왜 뜨나" 요약이 맞는 비율 · 보석 점수 상위 10편 "좋다" 비율 |
| **Step 3** | 모드 ④ (관심 분야 + 취향 진단 + 취향 카드) | 진단 결과가 "나 맞다" 는 응답 비율 |
| **Step 4** | 모드 ④ 리저브 주간 호 (AI 후보 + 사람 확정 · 새 호 알림) | 블라인드 비교 60% |

Step 1 은 LLM 없이 됩니다. LLM 은 Step 2(뜨는 말 정리·"왜 뜨나" 한 줄)부터 필요합니다. 최신 트렌드는 화면에서 맨 위지만, LLM 과 트렌드 자동 작업이 필요해서 Step 2 에 만듭니다.

## 10. 모드별 검증 지표

| 모드 | 지표 | 목표 (초안) |
|---|---|---|
| 공통 | 영상이 보이기 전 질문 수 | **2번 이하** (설계 규칙 · 3번 이상이면 결함) |
| 공통 | 첫 화면 → 첫 재생까지 누른 횟수 | 3번 이하 |

| ① 최신 트렌드 | 뜨는 말을 누른 사람 중 설명 영상을 70% 이상 본 비율 | 50% 이상 |
| ① 최신 트렌드 | "왜 뜨나" 요약 오류(사람 검수) | 5% 미만 |
| ② 생활 정보 | 내 토픽 저장 후 일주일 안에 다시 온 비율 | 40% 이상 |
| ③ 깊이 파기 | 결과 중 👍 비율 | 60% 이상 |
| ③ 깊이 파기 | 트렌드 키워드 칩을 누른 비율 | 30% 이상 |
| ④ 골라봄 리저브 | 블라인드 비교에서 골라봄을 고른 비율 | 60% 이상 |
| ④ 골라봄 리저브 | 5편 중 "좋았어요" 수 | 평균 2편 이상 |

※ 앱 안 재생이므로 "끝까지 봤나"는 YouTube 플레이어 이벤트로 잴 수 있습니다. Phase 0 에서는 잴 수 없던 값입니다.

## 11. 결정 필요

1. **모드 ④ 큐레이터의 실체** — (가) AI 후보 + 사람 확정 *(추천)* / (나) AI 만 · 이 경우 "큐레이터·전문가" 표현은 쓰지 않음
2. **모드 ④ 이름** — 골라봄 리저브 *(작업명)* / 큐레이터스 컷 / 골라봄 프라이빗 / 숨은 명작 5
3. **모드 ① 뜨는 말 출처와 요약 범위** — 인기 급상승 + 인기 검색어 *(추천)* · 사건·사고·건강은 요약 없이 영상만
4. **모드 ② 토픽 트리 확정** — §4 초안 8×5 그대로 갈지, 테스트 5명에 맞춰 바꿀지
5. **YouTube API 키 발급과 Cloudflare Worker** — 키는 사용자가 Google Cloud 콘솔에서 발급해야 합니다
6. **기획 문서 공개 여부** — 저장소가 공개라서, 이 문서를 푸시하면 누구나 볼 수 있습니다. 비공개로 두려면 문서는 저장소 밖에 두거나 비공개 저장소로 옮깁니다.
