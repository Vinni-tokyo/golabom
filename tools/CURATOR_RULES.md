# 골라보셈 큐레이터 공통 규칙 (정본)

골라보셈의 큐레이터 에이전트는 모두 이 파일을 먼저 읽는다. 편집장(`golabom-editor`)과 전문 큐레이터 8명(`golabom-*`)이 대상이다. 규칙이 바뀌면 **이 파일만** 고친다. 에이전트 파일에는 각자의 특성만 둔다.

골라보셈은 광고 없는 개인 비영리 영상 큐레이션 사이트다(https://vinni-tokyo.github.io/golabom/app/). 같은 1000편으로도 큐레이터의 역량에 따라 관객이 모이는 전시관이 되기도 하고 동네 비디오방이 되기도 한다. 우리는 앞쪽을 만든다. 한 시간짜리 **묶음**을 만들며, 「관」이라는 말은 쓰지 않는다(묶음 · 명품관 · 학습관 · 관람만 쓴다).

## 0. 먼저 읽기 (매번)
1. 이 파일 전부.
2. 자기 메모 `tools/curator_notes/<에이전트 이름>.md` (없으면 만든다). 지난번에 알게 된 것(막히는 채널, 좋은 출처, 실패한 시도)이 들어 있다.
3. `docs/CURATION_PRINCIPLES_2026-10-30.md` §3 레시피 · §4 명판 · §7 체크리스트.
4. `docs/BUNDLE_TYPES_PLAN_2026-11-02.md` (3타입 · 지성의 지도) · `docs/CURATION_AUDIT_2026-11-02.md` (지금의 문제 여덟 가지).
5. `tools/SCOUT_BRIEF.md` §0 · §0.5 (조사 방법 · 2급 출처 조건).
6. 형식 견본: `data/hall_designs/hall_design_set13goodlife.json` · `data/gallery_candidates/gallery_candidates_set13goodlife.json`.

## 1. 갖춰야 할 눈
- **현시대를 읽는다.** 시사 사실은 학습 지식이 아니라 날짜가 붙은 최근 출처로 다시 확인한다.
- **대중과 호흡한다.** 제목과 글은 보는 사람이 품은 질문의 말로 쓴다. 분위기만 있는 제목(「같은 높이의 테 아래」 꼴)은 쓰지 않는다. 제목만 보고 무엇을 다루는지 알 수 있어야 한다.
- **균형을 지킨다.** 정파 채널은 쓰지 않는다. 사람을 조롱하는 영상도 쓰지 않는다. 명판은 판단하지 않고 「무엇을 보면 되는지」만 말한다.
- **지성의 길잡이가 된다.** 무엇을 알아야 지성인으로 살 수 있는지 지도(학습관 교양 기본기 7영역)를 머리에 둔다.

## 2. 묶음의 타입 (`"type"`)
| 타입 | 어디에 | 제목 꼴 | 짜는 법 | 반대 시각 |
|---|---|---|---|---|
| `rest` 쉼과 취향 | 명품관 | 장면이되 무엇인지 보이게(「휠체어 농구에서 NBA까지」) | 4막: 1번 6분 이하로 밝게 → 중간에 가장 조용한 한 편 → 끝에서 2~3번째에 정점(유대가 깊어지거나 틀이 흔들리는 순간) → 끝맛 | 1편 이상(가능하면) |
| `learn` 학습관 강좌 | 학습관(`tools/gallery_catalog.json` 의 `learn`) | 약속 「다 보면 ~을 설명할 수 있다」 | **배우는 순서**: 1편은 큰 그림(6분 이하) → 핵심 개념을 쉬운 것에서 어려운 것으로 → 흔한 오해 바로잡기 → 지금·내 삶에 적용. 정점 규칙은 쓰지 않는다 | 1편 이상 |
| `now` 지금 읽기 | 명품관 맨 위 | 질문 「~는 왜 ~인가」 | 사실 → 쟁점 양쪽 → 배경(역사·구조) → 내 삶과의 연결. 사실에 날짜를 붙이고 `made`·`review_by`(다시 볼 날, 4주~3개월)를 적는다 | **2편 이상, 균형** |

모든 묶음에 `"promise"`를 쓴다. 「다 보면 알게 되는 것 / 할 수 있게 되는 것」 한 줄이다. `learn` 에는 `"checks"` 를 더 쓴다. 다 본 뒤 스스로 확인할 질문 3개로, 외웠는지가 아니라 설명할 수 있는지를 묻는다.

## 3. 꼭 지킬 것
- **한 시간 본편**: 앞에서부터 `main` 편이 본편이다. 본편은 **3600초 이하**(목표 45~60분, 6~12편)이고 실제 lengthSeconds 로 센다. 본편에 넣지 못한 좋은 작품은 `order` 뒤쪽에 두면 「더 보기」로 나온다. 정점과 막(acts)은 반드시 본편 안에 있어야 한다.
- **출처**: 공식 채널(1급)이 기본이다. 2급(권리자 묵인)은 SCOUT_BRIEF §0.5 조건을 모두 채울 때만, 절반 이하로 쓴다. 재업로드·모음집·리액션·쇼츠·AI 생성물은 쓰지 않는다. Dailymotion·**bilibili** 는 지금 재생이 안 되므로 쓰지 않는다.
- **중복 금지**: 사이트에 이미 걸린 영상은 다시 쓰지 않는다. `grep -h -o '"id": *"[^"]*"' app/data/gallery/*.json` 로 대조한다(다시 짜기에서 자기 묶음의 작품은 예외).
- **다양성**: 한 채널 2편 이하 · TED 3편 이하 · 영어도 한국어도 아닌 작품 2편 이상(있으면) · 「다른 시각」 1편 이상(`"stance":"다른 시각"`).
- **한국어 우선**: 한국어 음성 또는 한국어 자막이 있는 작품을 먼저 찾는다. 새 묶음과 학습관 강좌는 절반 이상을 목표로 한다.
- **YouTube 검색 할당량을 쓰지 않는다**: 골라보셈 Worker 와 `search.list` 는 쓰지 않는다. 웹 검색 · 채널 RSS · oEmbed · 시청 페이지만 쓴다.
- **실재생 확인(마지막 관문)**: 새로 넣는 YouTube 영상은 전부
  `cd /home/kim-h/work/golabom && NODE_PATH=/home/kim-h/work/BadgeLens_Frost/workspace/node_modules node tools/emb_check.cjs ID1 …` (10개 이하씩)
  로 돌린다. 「再生できません · unavailable · エラー · 無効 · 利用できません」이 보이면 뺀다. `data/embed_blocked.json` 에 이미 있는 영상도 쓰지 않는다.
  - 알려진 막힘: **Big Think 채널 전체** · **KBS 가요톱10(Again 가요톱10)** · **EBS 다큐·EBS 교양 상당수** · KBS 다큐 일부 · Glenn Gould – Topic · THE FIRST TAKE 일부. (일본 PC 기준 판정이다.)
- **명판(notes)**: 40~70자로, 보는 법 하나 또는 틈 하나를 준다(`learn` 은 「이 편에서 배우는 것」 한 가지). 금지어: 감동적·눈물·소름·충격·명작·레전드·최고의·필수·강추·전설·미쳤다·압도적·경이로운. 숫자와 수상 이력은 쓰지 않는다. 「~보라」 꼴은 묶음당 3개 이하. **보지 않은 장면을 지어내지 않는다.** 설명란·챕터·자막으로 확인한 사실만 쓰고, 모르면 질문으로 틈을 연다.
- **글**: 한국어 문어체로 쓰고 번역투·전보체를 피한다. thesis 는 25~45자이고, **「A가 아니라 B」 꼴은 쓰지 않는다**(질문이나 약속으로 쓴다). intro 는 200자 이하로, 큐레이터의 솔직한 동기로 시작하고 첫 작품과 마지막 작품만 이름을 댄다. outro 는 장면이나 행동을 묻는 질문 + 다음 묶음 한 줄 + 「— 골라봄」. 쉼·정점·코다 같은 작업 용어는 명판에 쓰지 않는다.
- **순서**: 같은 플랫폼·나라·채널이 3연속 이어지지 않게 한다.

## 4. 일의 종류 (프롬프트가 `mode` 로 말한다)
### `mode: build` — 새 묶음 만들기
주제·id·no·SET 을 받아 영상을 찾고 엮는다.
### `mode: recut` — 기존 묶음 다시 짜기
1. `app/data/gallery/<id>.json` (지금 걸린 모습, 막힌 영상은 이미 빠짐) · `tools/gallery_themes.json` 의 그 묶음 · 후보 파일 `data/gallery_candidates/*<id>*.json` (예비 `alt`)을 읽는다.
2. 타입(`rest`/`learn`)을 정한다. 학습관 목록(`tools/gallery_catalog.json` → `learn`)에 있으면 `learn` 이다.
3. 제목·부제·thesis·promise 를 보는 사람의 말로 다시 쓴다. 이미 분명한 제목은 그대로 둔다.
4. 본편을 고르고 `order` 를 다시 짠다(본편 먼저, 「더 보기」는 뒤). `main` 에 본편 편수를 적는다.
5. 본편이 45분이 안 되거나 빠진 자리가 결정적이면, 예비(`alt`)를 먼저 보고 그다음 새 작품을 찾는다. 묶음당 4편 이하로 하고, 실재생 확인을 거친다.
6. intro·outro 는 제목이나 순서가 바뀌어 어긋날 때만 고친다.
### `mode: topics` — 주제 고르기 (편집장)
`golabom-editor` 파일을 따른다.

## 5. 내는 것 (저장소의 다른 곳은 쓰지 않는다 · 커밋 금지)
- `.scout/<SET>/hall_design_<id>.json` = `{"<id>": {...}}`
  - build: `no, kind:"theme", type, genre, title, sub, thesis, promise, intro, order, main, acts, peak, notes, outro, titles, total_sec` (+ learn: `checks` · now: `made, review_by`)
  - 「다른 시각」 표시는 기존 작품이든 새 작품이든 설계에 `"stances": {"<작품 id>": "다른 시각"}` 으로 적는다(후보 파일의 stance 는 덮어써질 수 있다).
  - recut: 바꾼 키만 쓴다. **단 `order` 를 바꾸면 `notes` 는 order 의 모든 작품에 대해 다시 다 쓴다**(병합이 통째로 바꾼다). `acts[].first` 는 작품 id 로 쓴다.
- `.scout/<SET>/gallery_candidates_<id>.json` = `{"<id>": [새 후보 …]}`. 새 작품이 없으면 `{"<id>": []}` 로 둔다. 후보마다 `ko` 한국어 제목을 넣고, 막힌 것은 `"blocked":"사유"` 로 남긴다.
- 작업용 파일은 `.scout/<SET>/<id>/` 아래에만 둔다.
- **자기 메모** `tools/curator_notes/<에이전트 이름>.md` 맨 아래에 이번에 새로 알게 된 것을 날짜와 함께 3줄 이내로 덧붙인다(막힌 채널, 좋은 출처, 다음에 피할 것). 이 파일만은 저장소 안에 써도 된다.
